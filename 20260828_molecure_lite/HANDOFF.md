## 为什么是这些小节，不是整本书

两本图片书对着六个既有语料库量过一遍：`pesbexplain`、`pesbpro`、`labhandbook`、
生化层（含 68 个 `leh_*.js`）、`exam30`、`jiri_bank`，合计约 1900 万字符。

量的是两个指标，方法沿用 `molbio/tools/title_scan.py` 定下的那一条：

- **raw 命中** —— 这个词在语料里出现过多少次；
- **titled node** —— 有没有哪个节点的**标题**是以它命名的。

**只有第二个算数。**一个被当作步骤提了三百次的词，仍然是一个没人教过的题目。
PCR 在 pesbexplain 里出现 374 次，却只有一个节点是讲它的——这个案例当初正是
title scan 存在的理由。

46 个探针里：22 项 COVERED（**故意不收进来**）、8 项 THIN、8 项只被提及、
7 项近乎为零、1 项完全为零。本 app 收的是后四类。

扫描脚本留在
`…/scratchpad/molecular_coverage.py` 与 `crispr_scan.py`，可重跑。

### 两条必须记住的口径警告

1. **「基因敲除」第一遍判成 COVERED 是假的。** 探针正则里含 `crispr|cas9`，命中的是
   Lehninger 的一个节点。拆开单测：**ES 细胞打靶在六个语料库里得分全是 0**，
   Cre-lox 与敲除小鼠没有任何一个 titled node，CRISPR 本身被提 193 次而无一节点以它命名。
   这是整轮调查里最宽的一个缺口，也是 `M-6-2` 存在的理由。
2. **§7.5 固氮判成 COVERED 也是假的。** 命中的 4 个 titled node 是生化层的**氮代谢**节点
   （固氮的生化），不是 **nif 基因的调控**。所以 `M-7-5` 保留。

这个方法唯一测不出的，是**讲了但没用那个检索词**的题目。所以 COVERED 的判定值得抽查，
NEAR-ABSENT / ABSENT 才是硬结论。

## 引擎相对 biochemie_lite 改了什么

1. **localStorage 前缀 `biolite.` → `molbiolite.`**。七个 trainer 共用一个 `file://`
   origin，前缀相同就会互相覆盖星标、笔记和进度。`molbio/HANDOFF.md` 记过这个坑。

   **注意这个前缀故意不跟文件夹名走，也故意不带日期。**这个 app 的目录名是带日期的
   （`20260828_molecure_lite`），而带日期的目录早晚会被重新打日期。前缀一旦跟着目录名变，
   读者的星标、笔记、错题集和答题进度就会在一次改名之后静默失联——而且看起来会
   和「数据没了」一模一样。**目录随便改名，这个字符串别动。**
2. **删掉了「完整版」跳转。** 这个 app 没有姊妹全量版——它的源头是扫描书。原来三处
   指向 `../biochemie_pro/` 的链接会 404 并把用户扔到那个 app 上次打开的节点上。
   现在改成显示 `srcLabel(n)`：源书名 + 小节号 + 印刷页码。
   同理，`详见` 指向一个还没写 spine 的节点时，渲染成不可点的文字加「未写」，不再是死链。
3. **`AREAS` 换成本 app 的四个主题块**；`nodes.js` 增加 `src` 字段，去掉了
   `detail`/`nPoints`/`nTerms`（那三个是给全量版用的）。

入口页 `20260828_molecure_lite.html` 仍然 `<link>` 引用 `../biochemie_pro/style.css`——**这就是这个 app 必须
放在 bio-state-exam/ 下的原因**，相对路径和 `tools/topics.json` 都依赖它。

```bash
python tools/check-wiring.py           # 节点↔spine↔题目↔入口页 是否真的接上
python tools/check-mcq.py              # 选项长度偏倚与答案位置偏倚
python tools/jsbalance.py data/*.js    # 括号引号平衡
```

**写完必须跑，不要靠重读。** SPINE_SPEC 里写了原因：作者读了四遍也没发现 `phage`
被用了三次却从没被称作病毒。

### check-spine.py 相对上游改了三处，都是为了防「假通过」

1. **路径**。这个脚本比上游深一层（`<app>/tools/` 而不是 `bio-state-exam/tools/`），
   `parent.parent` 是 app 不是 repo。第一次跑它输出「0 spine，无问题」——
   **glob 匹配不到任何文件，读起来和通过一模一样。**
2. **加了两条断言**：一条 spine 文件都找不到，或者找到文件却解析出 0 条 spine，直接
   非零退出。上面那次假通过不能再发生。
3. **`nodes.js` 允许块注释**。上游那个是生成的裸 JSON，这个是手写的，组与组之间有
   注释说明为什么收这一节。解析前先剥注释，剥之前先断言没有字符串里含 `/*`。

### check-spans.py 是本 app 新写的

`app.js` 的 `claimOf()` 只渲染**那一个**加粗片段。字段里有多个加粗，就等于作者没有指定
结论，`claimOf()` 会把它们拼起来——上游实测中位数 393 字符、最坏 904，那已经不是极简了。
所以：**每个 `en`/`cn`/`title_*` 字段恰好一个加粗，且它单独拿出来要能读。**
当前实测：中位数 112，最大 250（上游参考：中位数 138–145，最大 243）。

批量修正用 `…/scratchpad/one_claim.py`：保留最长的那个加粗（结论），其余取消。
它**在长度差不到 1.5 倍时拒绝动手**并报出来让人工决定——已经拦下过两处，一处是我
压根没写结论级加粗，另一处是长度接近。

### check-wiring.py 查的是「静默失联」

三种故障都不会报错、页面照常渲染、内容就是不在：

- **ORPHAN SPINE**——spine 的 key 拼错一个字符，它就永远不会被显示，侧边栏看起来完全正常；
- **UNLOADED FILE**——`data/` 里有个 `.js`，入口页忘了 `<script>` 它；
- **ORPHAN AREA**——节点的 `topicKey` 不在 `AREAS` 里，它会掉进末尾的「其他」块。

### check-mcq.py 与它的阈值是量出来的

交接文档里记着母语料「89% 的题能靠选最长选项答对」。**这个数字没有被直接采信**，
而是用 `…/scratchpad/calibrate_mcq.py` 对 `biochemie_lite/data/questions.js` 重新量了一遍：

```
341 道题   最长即正确 51%（随机约 25%）
           最短即正确 12%
           答案位置   [0]=68  [1]=204  [2]=51  [3]=18
           正确项均长 144 字符 vs 干扰项均长 92（比值 1.57）
```

结论有两条：长度偏倚是真的，修过一轮之后仍是随机的两倍；**而位置偏倚比长度偏倚更严重
——那个题库 60% 的答案在第 2 个位置**，这是读者比选项长度更早会察觉的东西。

阈值：最长即正确 > 40% 判失败（随机 25%、母语料 51%，40% 取在中间，且不至于让 8 道题的
小题库因为一道运气不好就挂）；任一位置占比 > 50% 判失败（针对母语料那个 60%）。
**这两条都是斜坡上的切割，不是两个分离总体之间的空隙，所以具体数值不可辩护，脚本里
按「这是一个判断」如实写明，并且总是把原始计数印在旁边。**低于约 12 道题的题库，
比例没有意义，看计数。

## 写 spine 的两条经验（都是这次踩出来的）

**加粗不是强调，是选结论。** 第一版我把术语和结论都加粗了，20 步里 30 个字段有多个
加粗片段。极简模式下它们会被拼接，读者看到的不是一句话而是一串碎片。

**不要把自己知道的写进去。** §8.3 这一版教材里**没有** Xist、HOTAIR、SWI/SNF、MeCP2、
DNMT1、DNMT3a 这些词，它用的是 MeCP1 和「日常型／从头合成型甲基转移酶」。
凭常识补进去，就等于伪造了一段「读自这几页」的内容。要补标准知识，
用 `beyond: true` + `beyondNote` 说明它不在所引页面上。
